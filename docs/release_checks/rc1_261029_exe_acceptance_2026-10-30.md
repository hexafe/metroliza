- The archived EXE matches the hash and size above. It is a PE32+ x64 GUI binary with an empty
  security directory (unsigned).
- The payload was read without executing the EXE. The trailer manifest SHA-256 is `99576585…`,
  for version `2026.09rc1_261029-8f98a6efd014` and git SHA `b2510e0a…`. All 2174 file blobs
  matched their size and SHA-256.
- The payload has the same paths as the accepted onedir ZIP. 2154 files are byte-identical; 20
  are build outputs that differ (executables, native `.pyd`, `base_library.zip`, `RECORD`,

## Execution gap in the existing drivers

`scripts/qualify_windows_candidate_core.py` accepts only an onedir (`--artifact-dir`) with
sidecar provenance. It does not take a single launcher EXE. `scripts/qualify_windows_portable_onefile.py --kind launcher`
takes the EXE but covers only first launch, reopen, hard exit, incident export and extraction
cleanup. That coverage already passed on these bytes in job 123854029137. No existing driver
runs the core workflow (import, OCR, filter, group, export) or Excel locking on the launcher
EXE, so steps E4–E10 are manual.
